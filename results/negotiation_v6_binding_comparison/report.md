# 整计划与依赖范围证据：真实对照结果

预注册12run全部正常结束；无故障注入、无重跑。源码/案例哈希在完成分析时与执行前manifest一致，146条审计事件核验通过。

|指标|整计划绑定 full|依赖范围 dependency|
|---|---:|---:|
|有效/尝试|6/6|6/6|
|不安全最终提交|0|0|
|已授权任务完成|4/4|4/4|
|未批准任务拒绝|2/2|2/2|

实际查询少13.33%，token多4.67%。完成与拒绝数量相同，但模型产生的计划和修正路径不同，不能将全部查询差归因于绑定策略，也不能声称总体货币成本下降。

为检验机制，对全部12条真实轨迹作固定草稿的离线双绑定重放，使用相同静态owner检查、复用有效缓存。重放在原绑定条件下逐run复现实际查询数，证明本批没有过期等未建模因素影响该计数。全轨迹若按full绑定需30次，按dependency需27次；这不是另一批真实模型调用，也不是模型行为的反事实结果。

10条轨迹没有绑定差异。两条存在修正的真实轨迹中，一条full原run查询6次，相同草稿按dependency可用5次；另一条dependency原run查询4次，相同草稿按full需6次。它们支持“仅重验受影响承诺”的局部机制。样本很小，不作显著性或一般化声明。

本对照没有Autonomous条件，因此不能用它证明程序约束相对Agent自主流程的可靠性增量。下一步补齐该主对照，同时保留Agent自行请求确认的工具，避免刻意削弱baseline。计划质量和信息遗漏仍需独立评价，不能把硬条件满足当成业务最优。

原始数据：aggregate.json、records.json；配对重放与核验：analysis.json；每run的events.json、result.json、execution.json及validation.json均保留。执行前规范见根目录EXPERIMENT_v6_BINDINGS.md。
